# PNA deck: design system and component library

Build framework for `final/Priyanka_Nanda_Academy_Growth_Strategy.pptx`. Slides are written as
data and passed to components. Every component sizes its own text and reports anything that
cannot fit, so a storyboard can be turned into slides quickly without hand-placing shapes.

| File | Purpose |
|---|---|
| `theme.js` | Theme (12 scheme colours, fonts), colour tokens, type scale, grid, slide layouts |
| `components.js` | Deck builder (`createDeck`) and every slide component (`C.*`) |
| `fit.js` | Text measurement, wrapping and fitting. Logs a warning for any text that cannot fit at its floor size |
| `font_metrics.js` | Glyph widths for Calibri and Cambria, generated by `tools/gen_font_metrics.py` |
| `demo_build.js` | Builds `_component_demo.pptx`: one slide per component, with placeholder data |
| `qa.sh` | Validates a deck, then renders it to PDF and PNG in `_render/<deck>/` (git-ignored) |

`node_modules/` (pptxgenjs 4.0.1, already installed) is git-ignored at the project root.

## Commands

```bash
cd final/presentation_source
node demo_build.js                      # build the demo; prints any text-fit warnings
./qa.sh _component_demo.pptx            # validate.py, then soffice -> PDF -> PNG at 60 dpi
./qa.sh ../Priyanka_Nanda_Academy_Growth_Strategy.pptx   # same QA for the final deck
markitdown _component_demo.pptx         # text dump for content QA

node build_deck.js                      # final deck from deck_content.js (text and numbers live there)
./qa.sh ../Priyanka_Nanda_Academy_Growth_Strategy.pptx _render/deck 90
python3 tools/number_check.py ../slide_storyboard.md ../Priyanka_Nanda_Academy_Growth_Strategy.pptx
```

`qa.sh` wraps the pptx skill's scripts:

```bash
python3 /mnt/skills/public/pptx/scripts/office/validate.py deck.pptx
python3 /mnt/skills/public/pptx/scripts/office/soffice.py --headless --convert-to pdf --outdir _render/deck deck.pptx
pdftoppm -png -r 60 _render/deck/deck.pdf _render/deck/slide
```

Then open every PNG and check it. A build that prints no `Text-fit warnings` has no text below its
floor size and no overflow that the metrics can predict. It does not replace looking at the slides.

## Design system

**Palette.** Aubergine is the dominant colour, porcelain is the background, and rose gold is the
single accent. Contrast ratios are WCAG ratios.

| Token | Hex | Theme slot | Use |
|---|---|---|---|
| `aubergine` | 3D1A33 | dk2 | Titles, dark slides, emphasis tiles (15:1 on white) |
| `plum` | 5E2B52 | accent1 | Primary data colour |
| `rose` | C2705C | accent2 | Highlight bar, gate markers, numbered discs. Graphics only (3.6:1) |
| `roseDark` | A4513F | (hlink) | Accent-coloured text such as kickers and link labels (5.5:1) |
| `roseLight` | E7A995 | | Accent text on aubergine (7.5:1) |
| `mauve` | 9C8794 | accent3 | Muted secondary data, the conservative scenario |
| `porcelain` | F8F4F1 | lt2 | Content-slide background |
| `paper` | FFFFFF | lt1 | Cards, chart panels, tables |
| `ink` | 2B2129 | dk1 | Body text |
| `muted` | 6B5F67 | | Secondary text, axis labels, footers (5.5:1 on porcelain) |
| `plumTint` / `sand` / `line` | F2EAF0 / F1EAE5 / E4DAD5 | | "So what" panels and recommended rows / zebra rows / hairlines |

**Evidence badges.** Each type differs in both colour and form, so the types stay distinct in greyscale.

| Type (`badge:`) | Look | Meaning |
|---|---|---|
| `verified` (alias `fact`) | Solid green 2D6A5B | Sourced fact, checked |
| `estimate` (`est`) | Amber tint, amber outline | Our modelled number |
| `hypothesis` (`hyp`) | White, dashed slate outline | To be tested |
| `recommendation` (`rec`) | Solid aubergine | Our advice |
| `founder` | Mauve tint | Stated by the founder, not verified |
| `claim` | White, dotted grey outline | Third-party claim, not verified |

**Scenarios.** Charts colour scenarios by role, inferred from the name or set with `role`:
conservative is mauve, planning or base is plum, and upside or aggressive is rose.

**Typography.** Headings use Cambria and body text uses Calibri. Both ship with Office, and
LibreOffice renders them through the metric-compatible Caladea and Carlito, so QA renders show the
real line breaks.

| Element | Size |
|---|---|
| Assertion title | 28 pt, shrinking to a 22 pt floor; 2 lines maximum |
| Subtitle | 15 pt muted (floor 12 pt) |
| Kicker | 11 pt bold caps, rose |
| Body | 14 pt (floor 11 pt); dense cells and tables floor at 10 pt |
| Chart labels | 11 pt, theme body font |
| Footer (source and note) and badges | 9 pt |
| KPI numbers | Cambria, up to 44 pt (floor 26 pt); one size shared across a row |

The rupee sign is always set in the body font, even inside Cambria headings, because Caladea has
no ₹ glyph. Use `headRuns()` for any heading-font text that you add by hand.

**Grid** (inches, 13.333 × 7.5). Margins are 0.6 on each side. The kicker sits at y 0.36, the
title at 0.68 and the content area runs from 2.1 to 6.72. The footer is at 6.86 to 7.28, beside
the slide number. Blocks are separated by 0.3 gaps, and cards have a 0.08 corner radius.

**Motif.** The motif is a compact-mirror circle: a rose-gold ring and a soft disc on the cover and
dividers. It is echoed by circular gate nodes, numbered discs and pill badges. There are no accent
bars or title underlines.

**Layouts.** There are three: `PNA_COVER`, `PNA_SECTION` and `PNA_CONTENT`. Titles use the real
title placeholder, so screen readers and the outline view see them. The brand label and slide
number are placed on the layouts. The theme is written by `applyTheme()` in `deck.write()`.

## Using the components

```js
const { createDeck, C } = require("./components");
const { GRID } = require("./theme");

const deck = createDeck({ title: "Growth Strategy", subject: "PNA" });
deck.section("Opening");
deck.cover({ title, subtitle, meta });
deck.sectionDivider({ number: 1, title: "Where PNA is today", subtitle });   // also starts a section

const s = deck.contentSlide({ kicker, title, subtitle, source, note, notes }); // title + footer + speaker notes
C.addKpiRow(s, { items: [{ label, prefix: "₹", value: "66.5", unit: "L", period, badge: "estimate", emphasis: true }, ...] });

deck.appendixTable({ kicker, title, columns, rows, source });   // adds as many slides as it needs
await deck.write("../Priyanka_Nanda_Academy_Growth_Strategy.pptx");
```

Positions are in inches. Omitting `x/y/w/h` fills the whole content area. Split the area with
`GRID.ML`, `GRID.CW`, `GRID.top`, `GRID.contentH` and `GRID.gap`.

| Component | Key data |
|---|---|
| `addTitle(slide, {title, kicker, subtitle})` | Called by `contentSlide`. Uses a "stable" size so the subtitle placement is reliable |
| `addFooter(slide, {source, note})` | 9 pt, at most 2 lines, otherwise a warning |
| `addBadge(slide, {type, x, y, w?})`, `addBadgeLegend(slide, {x, y, types})` | Returns `{w, h}` |
| `addStatusChip(slide, {status: recommended\|second\|deferred\|rejected, label})` | Verdict pills |
| `addKpiTile` / `addKpiRow(slide, {items, y, h})` | `value, prefix, unit, period, label, badge, note, emphasis` |
| `addBarChart(slide, {categories, series, direction: col\|bar, highlight, stacked, numberFormat, title, unit, badge})` | Native chart on a card. `series` is `[numbers]` or `[{name, values}]` |
| `addScenarioChart(slide, {categories, scenarios: [{name, values, role?}], type: column\|line})` | Grouped columns with labels, or lines on a quiet axis (`showValue` turns line labels on) |
| `addMarketTree(slide, {levels: [{code, title, value, range, parts, note, badge}], links: [{label, sub}]})` | TAM → SAM → SOM; the last box is dark |
| `addFunnel(slide, {stages: [{label, sub, value, display}], conversionNotes, overall, scale: stepped\|linear, headers})` | Conversions are calculated unless `conversions` is given |
| `addScorecard(slide, {criteria: [{name, weight}], options: [{name, desc, scores, status, statusLabel, whyNot}], mode: harvey\|chip})` | Weighted score is calculated; includes a legend |
| `addGateTimeline(slide, {gates: [{code, name, when, criteria, unlocks, current}]})` | One shared criteria size across all gates |
| `addGantt(slide, {periods, groups, rows: [{label, heading, bars: [{start, end, label, tone}], milestones}], markers})` | Period units; `end` is exclusive. Tones are primary, accent, muted and dark |
| `addFindingsSoWhat(slide, {rows: [{finding, badge, soWhat, soWhatBadge}]})` | Paired rows joined by an arrow |
| `addDecisionList(slide, {decisions: [{title, detail, by, owner}]})` | Uses two columns when there are more than 5 decisions |
| `addTextBlock(slide, {heading, bullets \| paragraphs, card})` | Commentary beside a chart |
| `addTable(slide, {columns: [{header, w, align, bold}], rows, max, min})` | Cells are strings or `{text, bold, color, fill, tag}`. `tag` appends an evidence label |
| `deck.appendixTable({...})` | Uses the fewest pages possible at 10 pt, the largest size that keeps that page count, and balanced pages |

**Conventions.** Every shape has an `objectName`, and all text is in text boxes (`isTextBox`) or
placeholders. Colours go through `col(token)`, which returns scheme colours where a theme slot
exists. Charts use `hex()` because pptxgenjs writes chart colours only as sRGB.

## Limitations

- **QA fonts.** LibreOffice substitutes Carlito and Caladea for Calibri and Cambria. Their widths
  match, but kerning and hinting differ slightly, so wrapping is estimated with 3% slack.
  Borderline titles are shrunk until the line count is unambiguous.
- **Chart colours** are hex and do not follow a palette change made later in PowerPoint's Design
  tab. Shapes and text do follow it.
- **Funnel bars.** The default `stepped` funnel narrows the bars evenly and is not drawn to scale;
  the labels carry the numbers. Use `scale: "linear"` when the bar widths should be proportional.
- **Line labels.** Line-chart data labels are off by default because close scenarios collide.
- **Layout insets.** pptxgenjs does not write inset or anchor settings onto layout placeholders. A
  slide added by hand in PowerPoint from `PNA_CONTENT` gets default title insets; slides built by
  the code are unaffected.
- **Render artefact.** Hairline one-pixel steps on rounded bars at high zoom come from the
  PDF-to-PNG rasteriser, not from the deck.
